## 0. W3 在 B 路线下缩水了

原计划的 W3 是「CSF 106 条 L-Full 审核完成 → 立即跑第一轮盲测」。那 106 条已在
W2 生成完毕，因此 W3 只剩两件事：**盲测** 与 **签字入库**。

**顺序反过来：先盲测，后签字。**

签字的语义是「批准出厂」，成本是作者逐条读 106 条。盲测若未通过，这批内容要么重做
要么废弃，那 106 条的阅读时间就白花了。而盲测只需抽 10 条，用 `state: draft` 的内容
一样能跑。

因此本文档只覆盖盲测。签字入库挪到盲测通过之后（W3 末尾或 W4 开头），届时另行设计。

**本期真正的瓶颈不是代码，是人**：主 spec §7.3 要求 3–5 位**真正做过审计**的同行。
工装一两天可完成，人约不到就跑不起来。这件事没有技术替代方案。

## 1. 对照组的选择（已决）

主 spec §7.3 要求三份答案：(a) 本产品 Interpretation、(b) 裸问通用大模型、(c) 框架原文。
(b) 的具体做法 spec 未定，此处定死：

> **(b) 用与起草器同一个模型（DeepSeek `deepseek-chat`），配朴素提示词。**

被否决的两个替代方案与理由：

- **给对照组精心调过的提示词**：会把对照组做成一个不存在的对手。真实同行不会为每条
  控制精心调提示词。
- **换一个更强的模型**：引入模型能力这个混淆变量，输了无法区分是输在内容还是输在模型。

同一模型、一边有产品一边没有——**结论最干净**。这是对本产品最不利的公平设计：
若这样都能赢 70%，结论很硬；若输了，也不能赖对照组太强。

(b) 的提示词 **pin 死在代码里**，随 packet 一并记入报告，任何人可复现。

### 1.1 (c) 框架原文天然吃亏，结论里必须注明

CSF outcome 是英文，中文读者读它天然吃亏。它是「底线对照」而非真对手。

**结论中不得把「赢过 (c)」当作成绩。** 有意义的比较只有 (a) vs (b)。

## 2. 盲的边界（本设计最容易骗到自己的地方）

主 spec §7.3 只说「去除来源标识」。但本产品的解读是**七个结构化字段**，而裸问出来的
是一段散文——**评委不看内容、只看排版就能认出哪份是产品**。

若不处理，测出来的是「结构化排版讨不讨喜」，不是「内容有没有用」。

**已决：接受结构差异，如实记进限制（方案 C）。**

理由：结构本来就是 B 路线护城河的一部分。主 spec §7.3 改写后的假设原话是
「有内容图谱、有官方映射、每句话可回溯出处、**结构一致**」。把结构剥掉去比内容，
比的是一个本就不打算单独卖的东西。同行真实的选择场景就是「打开你的产品 vs
打开聊天框」，两边形态本来就不同——方案 C 最接近真实购买决策。

**代价写死进结论措辞：**

> 本轮只能声称「**这个产品比裸问更有用**」，
> 不能声称「**我们的文字比大模型的文字好**」——后者没测过。

被否决的替代方案：

- **三份都强制成七字段**：把结构送给对照组，等于自废武功。
- **把本产品的解读散文化**：同样丢掉结构，且散文化过程会损失内容。
- **跑两轮（整体一轮 + 统一结构一轮）**：更完整，但要约两次人。**留作盲测通过后的加试**，
  不进本期。

## 3. 抽样

`fr blindtest prepare --seed <N>`

**按 CSF 六个 function 分层随机**，比例照 106 条的实际分布：

| function | 总数 | 期望抽取 | 实抽 |
|---|---|---|---|
| GV | 31 | 2.9 | 3 |
| PR | 22 | 2.1 | 2 |
| ID | 21 | 2.0 | 2 |
| RS | 13 | 1.2 | 1 |
| DE | 11 | 1.0 | 1 |
| RC | 8 | 0.8 | 1 |
| **合计** | **106** | **10.0** | **10** |

配额按最大余数法从比例算出，不写死——106 条的构成若变（如补入废止条目的替代条），
配额自动跟着变。

纯随机可能抽出一堆治理条款，分层保证覆盖面。**seed 记进报告**：防止事后觉得结果
难看再换一批重抽——那是最容易发生也最难自察的作弊。

### 3.1 光记 seed 防不住重抽（2026-08-22 增补）

seed 只有配上**同一个抽样框**才谈得上复现。抽样框变一条（例如泄露词过滤的名单变了、
解读增删了一条），同一个 seed 就会抽出另一批题——而报告里那个 42 看上去毫无变化。

因此 `answer_key.json` 增记 `frame_fingerprint`（抽样框排序去重后的 sha256 前 16 位）。
`prepare` 若发现既有 answer_key 的指纹与当前抽样框对不上，**停下并说明**，
不静悄悄产出另一批题；要重出必须显式删掉 `build/blindtest/<seed>/`。
指纹为空（加这个字段之前出的题）同样视为无法验证，一样停。

**seed=42 这份题实测就撞上了**：见 `docs/superpowers/notes/w3-first-packet-run.md` 的
2026-08-22 更正。

## 4. Packet 与答案

每条控制出三份，标 **甲 / 乙 / 丙**，顺序**逐条独立随机**（同一份 packet 内，不同控制的
甲乙丙对应关系不同，评委无法从第一条推出后面）。

产出两个文件：

| 文件 | 内容 | 是否发给评委 |
|---|---|---|
| `build/blindtest/<seed>/packet.md` | 10 条 × 三份变体 + 答题说明 | **发** |
| `build/blindtest/<seed>/answer_key.json` | 字母 → 变体的对应、seed、(b) 的提示词与模型 | **不发** |

**构建断言：packet 中不得出现任何变体标识**——不得出现 `interpretation`、`basis`、
`provenance`、`inferred`、`practitioner` 等字样，也不得出现变体名。断言不过就不产出 packet。

控制编号**保留**（评委需要知道在评哪一条），因为三份变体共享同一编号，它不泄露来源。

## 5. 回收与统计

`fr blindtest tally --seed <N> --judge <名字> --picks "1=甲,2=丙,…" [--note "自由评语"]`

### 5.1 「三份都没用」（2026-08-22 增补）

原设计逼评委三选一。这样三份都是垃圾时，产品照样能拿到 70%——那个 70% 量不出任何东西。
因此 packet 的答题说明里增加一个选项，评委可写 `3=都没用`。

**算法（取最严的一种）：这类票计入分母、不计入任何一份的得票。** 弃权不替产品抬分。
两两对比 (a) vs (b) 里不含这些票——「都没用」不是投给任何一方的票。

改答题说明不该重抽一批题、也不该再花一次钱调模型，为此新增
`fr blindtest repacket --seed <N>`：只从 `variants.json` 重渲 packet，
并断言甲乙丙的对应关系与既有 `answer_key.json` 完全一致，对不上就拒绝产出。

每位评委一份 `build/blindtest/<seed>/verdicts/<judge>.json`。

`fr blindtest report --seed <N>` 输出：

1. (a) 被选场次占比，与 70% 线的对照
2. (a) vs (b) 的两两对比（**这是有意义的那个数**）
3. (c) 的得票（仅供参考，见 §1.1）
4. 评语中主动提到 `common_myth` / `auditor_asks` / `regional_note`，或提到「映射」「出处」
   的人数——对照主 spec §7.3 的第二条通过线
5. seed、(b) 的模型与提示词版本、评委人数

## 6. 通过线写死在代码里

主 spec §7.3：**「通过线（事前定死，事后不得修改）」**

- ≥ 70% 场次选择 (a)
- 至少 2 人**主动**指出 `common_myth` / `auditor_asks` / `regional_note` 有价值，
  **或**「能看到这条对应哪些别的框架条款、且对应关系标了出处」有价值

**这两个阈值是模块级常量，不接受命令行参数覆盖、不接受配置文件覆盖。** 要改必须改代码，
从而留在 git 记录里、必须写进提交信息、必须被 review。这是把「事后不得修改」从一句
自律变成一道机械约束。

## 7. 不做

- **不做网页/表单收集。** 3–5 位评委，手工回收的成本低于建一个后端。
- **不做统计显著性检验。** n = 10 条 × 3–5 人，主 spec §11 R4 已承认统计效力有限，
  做检验是假精确。
- **不做签字入库。** 见 §0，挪到盲测之后。
- **不做第二轮「统一结构」加试。** 见 §2，留作通过后的加试。

## 8. 测试

沿用 W1/W2 的纪律：**公有 CI 零网络、零 API key**，(b) 的生成走注入的 fake client。

必测：

1. 分层抽样在同一 seed 下完全可复现，且配额符合 §3 的表
2. packet 不含任何变体标识（这条是断言，也是测试）
3. 甲乙丙顺序逐条不同，且与 answer_key 一致
4. tally 解析、report 计算、通过线判定
5. 通过线常量**无法**被参数覆盖（写一条测试钉死这件事）

## 9. 未通过怎么办

主 spec §7.3：不是转去做 UI，而是先修解读的提示词与结构；两轮仍不过，说明
「接地 + 结构」不足以构成购买理由，届时要么回到 A 路线（作者亲自写差异化字段，
访谈管线仍在、未删），要么停止。

主 spec §7.4 新增的两条 B 路线止损同样适用，其中一条直接对应本轮：

> 盲测中同行主动说「这些我自己问模型也能问出来」→ 核心卖点不成立。
