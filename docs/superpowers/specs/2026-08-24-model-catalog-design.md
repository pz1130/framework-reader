# 模型目录：配完 key 自动拉取该厂商可用的模型

**日期**：2026-08-24
**上游**：主 spec §10.A（三条红线）、网页服务化设计 §6⑤（模型与 key）
**动机**：模型名现在是一个手填文本框。填错一个字符，要到起草跑起来才报错；
而各家的模型名既不好记也在变（`deepseek-chat`、`qwen-max`、
`deepseek-ai/DeepSeek-V3`、`llama-3.3-70b-versatile`）。

---

## 0. 先更正一句写错的话

主 spec §10.A 与 README 的红线三写着：

> 所有 client 由 `llm/registry.py` 组装并被 `GuardedClient` 包住，**出网只有这一条路径**。

**这句话在 2026-08-23 就已经不精确了。** 当前 `src/` 里有三个真实出网点：

| 出网点 | 干什么 | 携带内容吗 |
|---|---|---|
| `llm/openai_compat.py::_default_post` | chat 补全 | **携带**（控制条款、制度正文节选） |
| `llm/anthropic_adapter.py::_default_send` | chat 补全 | **携带** |
| `identity/entra.py::_default_fetch` | OIDC 发现文档、换令牌 | 不携带 |

红线三真正要保的是**内容**不外流，不是「进程只准发一个请求」。Entra 那条从来没被
当成违例，正是因为它一个字的内容都不带。

**因此措辞改为**：

> **凡是携带内容（控制条款、解读、配套文档节选）的出网，只有
> `llm/registry.py` 组装并被 `GuardedClient` 包住这一条路径。**
> 不携带任何内容的出网（身份 OIDC、模型目录查询）各自独立，
> 但必须满足：真实请求收在一个 `_default_*` 函数里、可注入替换、
> 有测试断言其不被测试触碰。

模型目录属于第二类。**这不是新开一个类别，是加入一个已经存在的类别。**

## 1. 拉什么

`GET {base_url}/models`，`Authorization: Bearer <key>`，**超时 15 秒**
（不是 chat 那个 120 秒——目录查询等 15 秒还不回，就当它不支持）。

Anthropic 走它自己的 `GET https://api.anthropic.com/v1/models`，
需要 `x-api-key` 与 `anthropic-version` 头。所以适配分两支，与 `preset.kind` 一致。

响应按 OpenAI 格式解析：`{"data": [{"id": "..."}, ...]}`。取 `id`，排序，去重。

### 1.1 过滤掉非对话模型

siliconflow 与 openrouter 的目录里有一两百条 embedding / rerank / tts /
whisper / moderation / image 模型。它们**永远不会被用作 drafter**，
留在下拉里只会让人翻不到想要的那条。

按 id 子串剔除：`embed`、`rerank`、`tts`、`whisper`、`audio`、`moderation`、
`image`、`vision-ocr`、`stable-diffusion`、`flux`。

**这份清单会误伤。** 某天某家把对话模型起名叫 `xxx-vision-ocr-chat`，它就被吃掉了。
代价可接受，因为**手填框永远保留**（§3）——误伤的后果是「下拉里没有，手填一下」，
不是「用不了」。

---

## 2. 什么时候拉

**保存 key 之后自动拉一次。**（2026-08-24 已决）

被否决的两个：

- **每次打开 `/models` 都拉**：每开一次页面就往所有配了 key 的厂商发请求，
  页面变慢，厂商那边看到一堆莫名其妙的调用。
- **只靠手动按钮**：多一步，而且很多人不会发现那个按钮。

拉取结果**缓存进库**，页面从缓存读。旁边一行小字写明「取自 {厂商}，{时间} 拉取」
和一个「刷新」按钮——**时间必须显示**：一份不知道多旧的清单，和没有清单一样危险。

---

## 3. 失败一律不阻断

**拉不到不影响存 key。** 三种情况分开说人话，且都保存 key：

| 情况 | 页面上说 | 记进缓存 |
|---|---|---|
| 401 / 403 | 「这把 key 被这家拒了——如果你确定它没错，可能是这家的目录接口要额外权限」 | 记 error，可刷新重试 |
| 404 / 解析不出 | 「这家不提供模型目录，模型名手填」 | 记 error |
| 超时 / 连不上 | 「拉不到，可以稍后点刷新」 | 记 error，可刷新重试 |

三种都可以点「刷新」手动重试；**没有任何自动重试**——自动拉取只发生在
保存 key 的那一刻（§2），页面加载不触发出网。

**为什么 401 也照存**：有些厂商的 `/models` 需要额外权限，而同一把 key 跑
chat 完全没问题。拿目录接口的拒绝去否决一把 chat 能用的 key，是把人卡死在
一个我们自己引入的关卡上。

**手填框永远保留。** 新模型上线永远早于任何目录；自定义端点与内网网关未必有
这个接口。**下拉是便利，不是唯一入口**——这条是硬约束，有测试钉住。

## 4. 数据

```sql
CREATE TABLE IF NOT EXISTS model_catalog (
    provider    TEXT PRIMARY KEY,
    models_json TEXT NOT NULL DEFAULT '[]',  -- 过滤后的 id 列表
    fetched_at  TEXT NOT NULL,
    error       TEXT NOT NULL DEFAULT ''     -- 空 = 这次拉成功了
);
```

落在 `llm/config.py` 已有的那个库里（`ModelConfig`），与 `provider_key`、
`custom_provider` 同库同一条 schema。**不新开一个库**：它是模型配置的一部分。

清 key 时一并清掉该厂商的目录——key 没了，那份清单也失去意义。

## 5. 界面

`/models` 页「角色用哪个模型」那一块，模型名那一栏从纯文本框变成：

```
模型名   [ 下拉：从目录里选 ▾ ]  或  [ 手填 ______ ]
         取自 deepseek，2026-08-24 15:20 拉取 · 刷新
```

下拉为空（没配 key / 拉失败 / 这家不支持）时**只显示手填框**加一句原因，
不显示一个空下拉——空控件让人以为坏了。

### 5.1 顺带白捡的：key 验活

拉取成功本身就证明了这把 key 能用。**「厂商一览」表里那一列「验活」因此有了
第二种含义**，两者要分清楚，不能混成一格：

- **未验活**：我们（作者）没拿真 key ping 过这家的端点——预设自带的属性
- **你的 key 通了**：这台机器上用你配的 key 成功拉到了目录——运行时事实

表里分两列。混成一列的话，「验活」到底在说谁，三个月后没人说得清。

## 6. 测试

真实出网只有 `catalog.py::_default_get` 一个函数，其余全部注入假 `http_get`：

- 各家响应格式解析（OpenAI 格式、anthropic 格式、字段缺失、空列表）
- 过滤规则：embedding/rerank/tts 被剔除；对话模型不被误伤（用真实模型名做样例）
- 三条失败分支各一条：401、404、超时——**都要断言 key 仍然保存了**
- 缓存命中不重复出网；「刷新」强制出网
- **手填仍然可用**：下拉为空时表单照样能提交一个手填的模型名
- 401 之后页面上不出现 key 的任何字符
- 「厂商一览」里**「未验活」与「你的 key 通了」是两列**（§5.1）：
  一个未验活的厂商在 key 拉通之后，两列同时为真且各自显示
- **新增一条全局断言**：`src/` 里出现 `httpx` 的文件只允许是
  `openai_compat.py`、`anthropic_adapter.py`、`entra.py`、`catalog.py` 四个。
  第五个文件里出现 `httpx`，测试就红——这条是 §0 那个措辞的机械保障，
  不靠人记得去看 spec。

`tests/test_no_network_in_tests.py` 的禁用清单加上 `_default_get`。

---

## 7. 不做

- **不做「自动选一个模型」**：拉到列表之后仍然由人来选。哪个模型适合起草解读
  是产品判断，不是可以从目录里推断的东西。
- **不做定时刷新**：没有后台任务，也不该为这个引入一个。
- **不缓存到内容包**：目录是这台机器上这把 key 的事实，不是要分发的内容。
