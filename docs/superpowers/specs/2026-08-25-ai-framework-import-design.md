# 从 Word / PDF 导入框架：让模型划边界，让代码截正文

**日期**：2026-08-25
**上游**：主 spec §7.3.5（导入自己的框架）、§9（受版权原文）、网页服务化设计 §6⑤（模型与 key）、模型目录设计 §0（出网点的分类）
**动机**：导入框只收 `.csv` / `.xlsx`。中文安全团队手上的制度九成是 Word，
其余是 Word 导出的 PDF——**没有人的管理办法长成一张三列表格**。
把它整理成表格这件事，正是这个工具本该替人做的。

---

## 0. 这不是「多支持两种文件格式」

`.csv` 与 `.docx` 的差别不在解析器，在**结构从哪儿来**。

| | 结构 | 错了赖谁 |
|---|---|---|
| CSV / XLSX | 用户填在 `编号,标题,正文` 三列里 | 用户的表有问题，报行号即可 |
| Word / PDF | **得从连续正文里推断** | 我们推错了 |

所以这不是给 `read_rows()` 加一个分支，是一条新管线：抽文本 → 推断结构 →
**人确认** → 落库。中间那步用模型做，而模型会错得没有规律。

### 0.1 一期不做扫描件

图片型 PDF 的 OCR 需要：扫描页检测、内嵌图片抽取、图片 payload（两个适配器的
`build_payload` 现在只拼文本）、以及**守卫怎么处理图片**——`PayloadGuard.check()`
逐段比对受版权原文，它只看得懂 `str`。图片走这条路时守卫是失效的。

这不是说扫描的公司制度里会有 Tier C/D 原文，而是**红线三的设计前提在这条路径上不成立**，
需要单独想清楚。它是一个独立子系统，只服务「图片型扫描件」这一种输入。

**一期做完能回答一个更要紧的问题：AI 切分到底准不准。** 那个答案直接决定
二期值不值得做。反过来，先把 OCR 管道铺好再发现切分本身不达标，那些工作全白做。

二期另出一份 spec。

---

## 1. 模型只划边界，正文由代码截

**这是整份设计的地基，其余都是它的推论。**

模型收到的是**带行号**的原文：

```
0012| 五、账号管理
0013| 公司应当为每一名员工分配唯一账号，禁止共用。
0014| 离职当日停用。
0015| 六、口令策略
```

模型回的是边界，**没有 `body` 这个键**：

```json
[{"ref": "5.1", "label": "账号管理", "parent": null, "from": 13, "to": 14},
 {"ref": "5.2", "label": "口令策略", "parent": null, "from": 16, "to": 21}]
```

落库的正文 = 原文第 13–14 行，**逐字不动**。

### 1.1 为什么不让它直接吐 JSON 带正文

因为它会**静默润色**。「离职当日停用」会变成「应在员工离职时及时停用其账号」。
两句意思差不多，但：

- 后面起草的解读、自评的证据、差距报告，全部基于这段正文；
- 而它不再是你公司的话，是模型的话；
- 且你**再也分不清**哪些字是原文、哪些是当时顺手改的。

主 spec 里「解读基于你实际要求」这个前提，就是在这一步塌掉的。

事后逐字校验（吐 JSON + 检查 body 是否逐字出现在原文里）不如边界法：润色是常态，
你会得到一屏标红的条目，而修正它们的办法只有重跑。**边界法让模型物理上编不了正文**，
它只能把边界划歪——而边界划歪在预览里一眼看得出来（正文头尾不对）。

### 1.2 提示词

`prompts/outliner.md`，继承 `prompts/extractor.md` 那部宪法：

> **你不是作者。你是抄写员。**

新增一条：**你不写正文，只划边界。** 输出里出现 `body` 键即视为格式错误。

## 2. 管线

```
上传 .docx / .pdf
  ↓ extract_text()            docx 现成（zipfile+正则，零依赖）；pdf 新增 pypdf
  ↓ 剔页眉页脚                 仅 pdf：跨页重复出现的行
  ↓ 逐行编号 → 原文快照落盘     ← 必须落盘，正文要靠行号从它截
  ↓ 估 token
  ↓   塞得下 → 一次调用
  ↓   塞不下 → 按 extract.chunk() 分块，逐块调用，再合并
  ↓ 校验（代码，不信模型）
  ↓ 预览态落盘
  ↓ 人勾选 / 改编号标题 / 往上合并 / 确认
  ↓ importer 落库
```

### 2.1 塞得下就一次过

一次过时模型看得到全文，章节层级与编号体系都在眼前，切得最准，
**而且没有跨块合并这个问题**——那是这条管线里最难写对的一块。

分块路径只为大文档存在。代价要说清楚：**它平时跑不到，所以真出事时它是没被验证过的那条**。
因此测试里两条路径同等对待，且分块路径的用例要覆盖「一条被切在块边界上」。

**「塞得下」的判据是一个固定的保守阈值，不是模型的真实上下文。** 目录接口
（模型目录设计 §1）只回模型 id，不回上下文长度，我们无从得知。所以取一个
所有在售对话模型都撑得住的字符数上限（`ONE_SHOT_MAX_CHARS`，初值 40000），
超过就分块。估错的后果是多分一次块，不是失败——所以宁可保守。

不引 tokenizer：为一个「宁可估小」的判断引一个依赖不值。

### 2.2 校验：一条都不信模型

| 检查 | 不过怎么办 |
|---|---|
| `from ≤ to`，两者都在 `[1, 行数]` 内 | 丢弃该条，预览页报「模型给的行号越界」 |
| 区间互不重叠、按 `from` 递增 | 同上 |
| `ref` / `label` 非空 | **保留但默认不勾选**——空标题多半是切歪了，但也可能是真条款，不替人决定 |
| `parent` 是本次出现过的某个 `ref`，或 null | 降级成 null，预览页标出来 |
| 输出不是 JSON 数组 / 含 `body` 键 | 整块作废，预览页报「模型没有按格式回」 |
| **有行不被任何区间覆盖** | 预览页明写「原文第 X–Y 行没能切出条款」 |

最后一条是硬要求。`userframework/importer.py` 开头写着：

> **坏行一律报错并指出行号，绝不静默跳过**——静默跳过的结果是用户以为全导进去了。

同一条规矩。整份都切不出（有人传了会议纪要）就显示 0 条加一句说明，不落库。

## 3. 预览态落盘，不在内存

`web/jobs.py` 的注释说进程内状态不落盘可以接受，理由是：

> 起草的结果在用户库里，丢的只是「跑到第几条」。

**这里不成立。** 预览态的结果还没进用户库——`fr serve` 重启一次，
用户已经花掉的那几十次调用就没了，且他不知道为什么，只能再花一次。

所以用户库加一张 `import_draft`：草稿 id、框架编号与展示名、**原文快照**、
切分结果、创建时间、创建人。原文快照必须一起存，否则确认落库时截不出正文。

草稿是临时的：确认或放弃后删除。没有回收逻辑——一期不做，
留着的草稿在 SoA 之类的地方都看不见，它只是几行文本。

---

## 4. 花钱的闸：同一本账，但开跑前预检

「条」在这个产品里的定义是**一次模型调用**（`views.py`：账记在「条」上不记在
「元」上，我们没有各家的实时价目，折成钱只会给人一个精确的错觉）。
导入调用和起草调用是同一种花费，分两本账要新增两个上限、两套解释。

**但必须预检。** 开跑前算出这份文档要几次调用（= 分块数，一次过即 1），
剩余额度不够就当场拒绝并说清差多少——跑到一半没钱了，那半份预览是垃圾，钱也白花。

预检不通过时**一个请求都不发**。这条要有测试。

### 4.1 谁能导文档

表格导入的门槛是 `framework:import`，不变。

**文档导入要同时有 `framework:import` 与 `interpretation:draft`。** 因为它花组织的钱，
而角色表把这件事分得很清楚（`identity/permissions.py`）：

> admin —— 管系统。**不含起草与确认**：起草花的是组织的钱。

admin 传一份 Word 上来就绕过了这句话。author 两个权限都有，不受影响；
admin 要用就先给自己加 author——而那一步会进审计日志，提权留痕正是要的。

导入本身照旧记一条审计；文档导入额外记调用次数。

## 5. 界面

### 5.1 导入框

`accept` 改成 `.csv,.xlsx,.xlsm,.docx,.pdf`。

**现在的 `accept=".csv,.xlsx,.xlsm"` 是「导入按钮无法使用」的真正成因**：
文件选择器把用户手里的 Word / PDF 全灰掉，选不中文件，看起来就是按钮没反应。

表格与文档两条路在同一个表单里，按后缀分流：表格走 `importer.read_rows()`
直接落库（今天的行为，一个字不改），文档走本 spec 的管线。

### 5.2 预览页

```
切出 47 条。确认前不写库。

 ☑ [5.1  ] [账号管理        ]  ↑合并
     公司应当为每一名员工分配唯一账号，禁止共用。
     离职当日停用。                      原文 13–14 行

 ☑ [5.1.1] [账号申请与审批    ]  ↑合并
     新入职员工由部门主管提交申请…        原文 15–19 行

 ☐ [5.1.2] [                ]  ↑合并      ← 标题空，已取消勾选
     （见附件一）                        原文 20 行

 ⚠ 原文第 88–96 行没能切出条款

[导入勾上的 46 条]
```

能改的只有三件：**取消勾选**、**改编号与标题**、**与上一条合并**。

**正文只读。** 它是原文——能在这儿改就等于把 §1.1 刚防住的「改写原文」
从前门放进来。切歪的主要形式是多切了一刀（一条被劈成两条），
「与上一条合并」把两段行号区间接起来就按回去了，正文自动重算。
少切一刀（两条粘成一条）没法在这儿拆，但它罕见得多。

`⚠` 那一行不可关闭、不可勾选——它是告知，不是待办。

**「与上一条合并」指的是列表里紧邻的上一条，不管它勾没勾。** 合并后：
行号区间取两者的并集（两段之间若有未覆盖的行，一并并进来——那正是想要的），
编号与标题取**上一条**的，勾选状态取上一条的。第一条没有「↑合并」。

### 5.3 异步

一份文档几十次调用要跑几分钟，同步 POST 就是一个转圈的白页，
而刷新会再点一次、再花一次钱（`jobs.py` 开头那段话）。走 `jobs.py` 加一种任务，
页面轮询进度。

## 6. 出网

抽结构走 `extractor` 角色——那个角色现在闲置，`views.py` 里它的描述本来就是
「从作者原话里抽结构」。**这正是它。**

payload 是用户自己上传的公司制度正文。`importer.py` 已经就这件事表过态：

> 用户自己公司的制度原文。他的文档、他的机器、他的 key——可以拿去起草。
> 与 Tier C/D 的受版权标准原文完全是两回事，后者永远不许出网（主 spec §9）。

因此走既有的 `llm/registry.py` → `GuardedClient` 这条路，**第一类出网，不新增出网点**。
`tests/test_no_network_in_tests.py` 的白名单一个字都不用改——要是它红了，
说明这个设计走错了。

新增依赖只有 `pypdf`，且只为 PDF 的文字层。docx 那条路保持零依赖。

## 8. 测试

**核心那条必须有，且要能独立说明整份设计**：

> 落库的正文，逐字等于原文对应行。

其余：

- 模型吐非 JSON / 吐空数组 / 吐了 `body` 键
- 行号越界 / 区间重叠 / `parent` 指向不存在的 ref
- 有行不被覆盖 → 预览页报出行号
- 一次过与分块两条路径**同等覆盖**，分块要有「一条被切在块边界上」
- 额度不够时**一个请求都不发**
- 预览页改编号标题、取消勾选、与上一条合并，各自落库后的结果
- 草稿确认后被删；重启不丢（落盘）
- 出网点白名单不变

模型一律注入假的。真实调用只在手工验收时跑，与 `fr llm check` 同一个规矩。

## 9. 不做

- **扫描件与 OCR**（§0.1，二期）
- **拆分一条**：预览里只能合并，不能拆。少切一刀罕见，为它做一套交互不值
- **草稿回收**：确认或放弃即删，没有过期清理
- **改正文**：§5.2，这是设计而非省略
- **记住上次的切分偏好**：每份文档独立，不学习
