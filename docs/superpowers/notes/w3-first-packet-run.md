## 2. 已修的两个工装缺陷

### 2.1 位置效应和变体混在一起

逐条独立 `rng.shuffle` 在 seed=42、n=10 时抽出的牌面是 **甲 有 8 条都是裸问**。
不是 bug（shuffle 本身均匀），是 n=10 的坏运气；但 spec §4「评委无法从第一条推出
后面」这条保证实际上失效了，而当时的测试只断言「布局种类 > 1」，8/10 相同也能过。

改成平衡随机（六种排列整批打乱后发），现在：

```
甲 {'product': 3, 'bare': 4, 'original': 3}
乙 {'product': 4, 'bare': 3, 'original': 3}
丙 {'product': 3, 'bare': 3, 'original': 4}
```

### 2.2 裸问的正文标题和字母标题同级

裸问回答 **10/10 都带 `###` 三级标题**，5/10 带表格——与 packet 用来分隔甲乙丙的
`### 甲` 同级。渲染出来正文小标题和另外两份材料平起平坐，既难读，也是一条来源线索。
现在变体正文里的标题一律降到 4 级以下（代码围栏内的井号不动），一个字不改。

重建 packet 时**复用了原来的模型输出**（从旧 packet.md 逐字抠回 `variants.json`），
没有重跑 API——重跑会拿到不同的裸问回答，等于中途换了对照组。

## 3. 未修的：spec §2 的前提被实跑证伪

spec §2 判断「结构是本产品这边的护城河」，依据是「裸问出来的是**一段散文**」。
实跑出来的 (b) 不是散文：

```
出题时   产品  6472 字 / 裸问 20222 字 / 框架原文 1186 字   裸问 = 产品的 3.1 倍
补映射后 产品 11677 字 / 裸问 20222 字 / 框架原文 1186 字   裸问 = 产品的 1.7 倍
```

（补映射见 §4——那不是为了缩小篇幅差做的，是把本来就该上场的内容放上场，
篇幅差缩小是副作用。）

裸问的答案有五级小标题、有证据清单表格，并且：

| 内容 | 裸问 | 产品 |
|---|---|---|
| 「审计员会问 / 追问」 | 4/10 | 10/10 |
| 「常见陷阱 / 误解」 | 1/10 | 10/10 |
| 地域差异 | 0/10 | **1/10** |

`regional_note` 全库 106 条只有 21 条非空，抽中的 10 条只有 1 条有。

问评委「哪份对你最有用」，一边 650 字一边 2000 字——**这测的有多少是内容、有多少
是篇幅，本轮没有剥离**。这个混淆变量现在会打印在 report 上，但打印不等于解决。

这正对着主 spec §7.4 的止损线：「同行主动说『这些我自己问模型也能问出来』→
核心卖点不成立」。

**约人之前先自己盲读一遍这 10 条。**3–5 位真做过审计的同行是本期最贵、且一次性的
资源，不该拿去测一个已经知道会歪的问题。

## 4. 已修：产品变体补上了映射与出处

原来 `render_product` 只渲染七个字段。第二条通过线的 OR 分支
（「能看到这条对应哪些别的框架条款、且对应关系标了出处」）以及
`ADVOCACY_MARKERS` 里的「映射」「出处」，评委在 packet 里根本看不到——
B 路线护城河的一半没上场，那半条通过线永远不可能被触发。

现在产品变体末尾多一段：

```
**对应到别的框架条款**
- NIST SP 800-53 Rev. 5（相关，1 条）：PM-11 Mission and Business Process Definition
- 对应关系的出处：NIST-OLIR-csf-2.0-to-sp800-53r5（官方映射），逐条可回溯
```

**只取可导出的边**（L1/L2_PUBLIC/L3）。L2 推导边 R7 抽样 correct 17%，
按主 spec §3.3 不进导出物，自然也不进评委眼前。抽中的 10 条共 140 条可导出边，
**全部 L1_OFFICIAL、全部来自同一个 NIST OLIR 官方映射文件、无一含泄露词**，
逐条边数 1 – 40。

「出处」指的是**映射**的出处，不是字段的：spec §4 把 `basis`、`inferred` 列为
泄露词，字段级依据本来就不许出现在 packet 里。实际上抽中 10 条的 61 个非空字段
`basis` 全是 `inferred`，就算允许也没有信息量。

**一个要自己看清楚的观察**：ID.IM-02 的 40 条边里有 19 条是各族的 `-1 Policy and
Procedures`（AC-1、AT-1、AU-1、CA-1 …）。这是 OLIR 映射本身的噪声，不是渲染的
问题。没有过滤——为了让 packet 好看去筛边，就是为了考试改产品。评委如果说
「这一串没用」，那是关于映射质量的真实反馈，该收下。

## 5. advocates 是关键词匹配，不是判断

`ADVOCACY_MARKERS` 子串命中即计数，「看不出误解那段有什么用」也算一个 advocate。
最容易自欺的那条通过线，判据是 substring。

没有改成语义判断（那要么引入模型判定、要么引入人工标注流程，都超出本期）。
改成：report 逐条打印评语原文，并写明 advocates 需人工确认后再采信。

## 6. 结论

工装可用，可复现，泄露断言有效，护城河已上场。**剩下的卡点只有一个：人。**

3–5 位真正做过审计的同行还没约到——spec §0 开篇就写了这是本期真正的瓶颈，
「工装一两天可完成，人约不到就跑不起来」。现在正是那个状态。

§3 的篇幅混淆变量仍未剥离（只做了仪表化，report 会打印）。按 spec §2 的方案 C，
这是接受的代价，但结论措辞必须守住：**只能说「这个产品比裸问更有用」。**

## 7. 2026-08-22 更正：这份题的抽样框不是 103 条，是 106 条

上面第 1 节写的「排除 3 条后在 103 条上重算」**只有配额那半句是对的**。实测发现，
盘里 `build/blindtest/42/` 那份题是从**未过滤的 106 条**里抽的。

**证据**（可自行复现）：

```
stratified_sample(全部 106 条, 10, 42) == answer_key.order   → True
stratified_sample(过滤后 103 条, 10, 42) == answer_key.order → False
```

两者只差最后两条：盘里是 `RC.CO-04` / `RS.MA-05`，用 103 条重跑得到
`RC.RP-04` / `RS.AN-08`。差异正好落在 RC 与 RS 两层——被排除的 3 条
（RC.RP-05、RS.AN-06、RS.AN-07）就在这两层里，其余四层不受影响。

**成因（推测，证据是文件时间）**：`build/blindtest/42/` 下 8 个文件的 mtime 全是
13:26:48，包括两个 `.bak`——`mv` 会保留原时间，全部相同更像是整目录 `cp -R`。
合并提交 `fd764df` 在 13:26:26，即出题跑在带有旧抽样逻辑的 worktree 里，
产物在合并之后被整个拷回主仓。`bb01076`（12:38）之后的主线代码是从 `frame` 抽的。

### 影响分开看

- **这份 packet 本身干净，可以发。** 被排除的 3 条一条都没被抽中
  （`answer_key.order` 与 `excluded` 无交集），`build_packet` 的泄露断言也过了。
- **spec §3 那条「seed 记进报告以防重抽」的保证当时是空的。** 谁拿 seed=42
  重跑都会得到另一批题，而报告里那个 42 看不出任何变化。

### 处置（已做）

1. **不重抽**。重抽等于丢掉一份已花过钱、已验证不泄露的卷子，换来的只是记录好看。
2. 新增抽样框指纹（spec §3.1）。已给这份 answer_key 补记**出题时**的指纹
   `7fd847862cfde787`（106 条），当前抽样框是 `fda4fd8df1096083`（103 条）。
   现在跑 `fr blindtest prepare --seed 42` 会停下并报出这两个值，不会静悄悄换题。

**发出去时要一并说清楚**：这份 packet 用的是 pre-`bb01076` 的抽样框，
seed=42 在当前代码下不复现；下一轮（第二个 seed）起才具备真正的可复现性。
