## 1. 成立的部分：严格抽取

`DE.CM-01` 一轮下来，三个差异化字段的 lint 忠实度**全部 1.00**：

```
common_myth : 1.00   auditor_asks : 1.00   regional_note : 1.00
```

字段值逐字来自作者原话，**没有润色、没有编造、没有补空**。W2 spec §2.3 那条
「只许删、切、重排」的设计在真实模型上成立——而且用的还是一个能力偏弱的模型。

这条结论很重要：**下一轮若仍不理想，要怀疑的对象不是「严格抽取」这条路线。**

## 2. 修掉的四个缺陷

均由这次实跑暴露，已在 `95429fa` / `fe8c03b` 修复并有回归测试。

### ① 起草器不验型，坏形状会静默进库

MiniMax 把 `evidence` 按 `practice` 的三档字典形状返回，**3/3 可复现**：

```
evidence = {'1': '网络监控日志记录。', '2': '安全事件响应计划和团队。', '3': ...}
```

`Field.value` 的类型是 `str | list | dict | None`，Pydantic 什么形状都收，schema
拦不住。起草器当时只验了 `practice`。**一半也是提示词的锅**——`evidence` 紧挨着
三档的 `practice`，模型照抄了形状。两边都补了；`prompt_version` d1 → d2。

### ② Q2 措辞预设了一套标准问法

原文「审计员会追问哪几句？」，作者当场反驳：**「每个审计员问的问题都不一样啊」**。

106 条要问 106 遍，第一条就卡住。改为锚在个人经历上：

```
你自己被问过的那几次里，审计员最常往哪儿戳？一句就够。
```

### ③ Q3 不知道有哪些落点，问出了没地方落的问题

模型生成的第 3 问是「IDS 部署后，还需要哪些措施来确保监控的有效性？」——
答案天然属于 `practice`，而抽取器不许碰起草字段。**这是提示词里明令禁止的
那种空问，它还是问了**，因为它根本不知道只有三个字段可落。

提示词补了三个字段的表格与禁例；`prompt_version` q1 → q2。

### ④ 抽取器静默丢答案 —— 最严重的一个

作者第 3 答「**接入siem，写usecase**」一个字都没进任何字段，也没有任何提示。

这是三句里最有从业味道的一句（"写 usecase" 是做检测工程的人才用的说法，
通用大模型不会这么讲），被管线吃掉了。

修法不依赖模型自觉：新增 `lint.unplaced_answers()`，按字符二元组重合度算哪几答
没落地，纯代码判定；结果存进 `interview.unplaced`，`$EDITOR` 中顶格显示：

```
# ⚠ 答3 没进任何字段，原话是：接入siem，写usecase
#   —— 想留就手动补进下面某个字段，不补它只留在 interview.raw 里。
```

拿当次真实数据回测，答 3 被准确抓出。

## 4. 一个只有实跑才会看清的问题：两条渠道以相反方式失真

这次是在**聊天里**做的访谈，不是终端。两者不等价，而且偏差方向相反：

| | 聊天（本次） | 终端（W3 的真实形态） |
|---|---|---|
| 追问 | 有人会追问、会澄清歧义 | 无人。模型只会把含糊原话原样收下 |
| 污染 | **高**。澄清时容易把提问者的措辞混进字段 | 低 |
| 产出 | 更细，但可能不是作者的话 | 更糙，但一定是作者的话 |

本次实际发生过一次：作者答「实际情况和预期往往有很大差别」，含义不明；提问方
列了三种读法请其选择，作者答「按 1」——**此时落进字段的会是提问方的句子**，
盖上 `basis: practitioner` 与作者签名。已当场中止，未采纳。

**记住这条**：任何由提问方提供候选措辞的做法都是污染源，即使作者点头认可。
终端形态没有这个风险，但它换来的是信息更薄。

## 5. MiniMax 起草质量不足

类型问题修好后内容仍是这样：

```
outcome  : Networks and network services are monitored to find potentially adverse events
intent   : 监控网络和网络服务以发现潜在的不良事件          ← 逐字翻译
plain_zh : 确保对网络和网络服务进行监控，以便及时发现和响应可能发生的不良事件  ← 仍是翻译
```

spec §3.4 对 `intent` 的要求恰是「**不是翻译条文**」，提示词里已明令禁止，
`abab6.5s-chat` 仍然照翻。

**影响**：三个差异化字段不依赖初稿，慢的那部分不受污染；受影响的是作者在
`$EDITOR` 里顺手修 `intent` / `plain_zh` 的时间。因此这条路量出来的耗时是**上界**。
拿到更强的 key（DeepSeek / Anthropic）后应改回 `roles` 并 `fr draft --force` 重跑。

## 7. 给下次跑的人（大概率是三天后的作者本人）的提醒

1. **状态不对就别跑。** 硬跑出来的薄答案会得到一个假的否定结论，比没有结论更糟——
   它会让你以为方法论已被证伪。本次中止即为此。
2. **别让任何人给你候选措辞**，包括 AI。宁可留 `null`。
3. 答不上来就留空。`regional_note` 在很多控制上**本来就没有内容**，空着是诚实。
4. 判定只看陌生控制。黄金控制你亲手写过，答起来快，但那是复述，不算数（spec §8.0）。
