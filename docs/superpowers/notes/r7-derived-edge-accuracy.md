## 判定规则

判据是 spec §3.3：**这条边能不能拿去给审计员当依据**，而不是「看起来有点关系」。

可用材料（controller R5）：

- CSF 2.0 公开 outcome 文本
- ISO 控制**编号** + 本库自写中文 label
- SP 800-53 Rev5 公开标题（`via` 中间节点）

不引用 ISO 官方措辞，不读取 `original_text`。

判定取值：`correct` / `partial` / `wrong`。

| 取值 | 含义 |
|---|---|
| `correct` | 两端活动对齐，可以把 CSF 侧证据交给审计员讨论对应的 ISO 编号 |
| `partial` | 同域近邻或支撑手段，但活动/时点/粒度不对；不能单独当依据 |
| `wrong` | 主题或方向不成立；通常是过宽中间控制把无关两端焊在一起 |

## 分布

| verdict | 条数 | 占比 |
|---|---|---|
| correct | 5 | 17% |
| partial | 10 | 33% |
| wrong | 15 | 50% |
| **合计** | **30** | **100%** |

**correct 率 = 17%（5/30）**。

即便把 `correct + partial` 算作「还算同域、或许可当审核线索」，也只有 50%。`partial` 里多数是 ISO **兄弟条款**（A.5.19 / A.5.20 / A.5.22；A.8.8 / A.8.32；A.8.15 / A.8.16；A.5.26 / A.5.28；A.5.33 / A.8.13）被焊错，审核队列会把时间花在否决假阳性上。

## 典型错误模式

### 1. 中间控制过宽（主因）

传递推导把「两边都连到同一个 800-53 控制」当成 CSF↔ISO 关系。若干 800-53 控制是超级枢纽：

| 中间控制 | 公开标题 | 样本中的后果 |
|---|---|---|
| `IR-4` | Incident Handling | 把事件宣布、事态研判、事件处置、复盘改进、启动恢复焊成完全图 |
| `SA-9` | External System Services | 台账、供方盯防、项目安全、角色职责、管理层义务都经此冒出来 |
| `XX-1` 家族头 | Policy and Procedures（本样本最多 18 条并行） | 任何「政策/合规/战略复核」都可能连到 A.5.31 或 A.5.36 |
| `CP-2` | Contingency Plan | 环境威胁防护被拖到 A.5.2 |
| `AC-2` | Account Management | 网络监控被拖到权限授予与收回 |

总体里含 `IR-4` / `SA-9` / `AC-1` 的推导边各约 75–77 条（727 的 ~10% 量级/枢纽），样本里枢纽边的正确率明显低于窄中间节点。

ISO 侧扇入同样放大噪声：A.5.2（角色与职责）有 32 条 L2 边，因其 L1 对照了 28 个 800-53 控制。

### 2. 粒度与生命周期不匹配

CSF outcome 是窄结果；ISO 编号是另一套切法。两跳不保持阶段：

- DE.AE-08（按准则**宣布**事件）→ A.5.25 事态研判：`correct`
- 同一 CSF、同一 `IR-4` → A.5.27 事件复盘改进：`wrong`
- RS.MA-05（**启动恢复**的准则）→ A.5.25：`wrong`

A⊇B 且 B⊇C 不蕴含 A 与 C 可举证（spec §3.3 原文理由，本抽样证实）。

### 3. 兄弟条款错位

供应链与技术域里，正确的 ISO 编号往往在**旁边**：

- GV.SC-05 把要求写入合同 → 样本落到 A.5.22，更贴 A.5.20
- GV.SC-07 关系存续期盯防 → 落到 A.5.20 为 `partial`，落到 A.5.22 才 `correct`
- PR.PS-02 按风险维护软件 → A.8.8 为 `correct`，A.8.32 只是变更手段
- PR.DS-11 备份 → 样本落到 A.5.33 记录保管，更贴 A.8.13
- DE.CM-01 网络监控 → 样本落到 A.8.15 日志记录，更贴 A.8.16

「同域」不够。审计员要的是**这一条**编号的证据。

### 4. 依赖方向反了

GV.OC-04 是外部干系人依赖**本组织**的关键服务；A.5.22 是盯防**供方**服务。中间 `RA-9` Criticality Analysis 只说「关键」，不区分方向。

## W4–W5 决定

| correct 率 | 决定 |
|---|---|
| ≥ 60% | 推导边可作为审核候选，W4–W5 按原计划 |
| 30–60% | 推导边仅作参考，ISO 侧工时上调 30–50% |
| **< 30%** | **推导边基本无用，ISO 的边改为全部走 L4 初稿；回 spec 修订 §7.2 并重估 W4–W5** |

本抽样 **17% < 30%**，落入第三档。

对 W4–W5 的具体含义：

1. **不要把 727 条 L2 推导边当作 ISO 映射审核队列。** 确认假阳性的成本高于从 L4 起稿。
2. **CSF ↔ ISO 的边全部走 L4 初稿 + 人工确认升 L3**，与 PCI / NIS2 等无官方表的框架同一条路。L2 边继续留在库内（spec §3.3：不可导出），至多给 L4 起草人当**隐藏提示**，不得进入导出物或审核默认候选。
3. **回 spec 修订 §7.2**：删掉「W4–W5 还要确认一批推导边」作为起始覆盖的假设；ISO 93 条 L-Full 之外，映射工作量按 L4→L3 重估，而不是「确认两跳候选」。本任务不改 spec 正文，只记录必须修订。
4. 若后续要救推导器，优先做的不是加大抽样，而是：**压枢纽**（IR-4 / SA-9 / XX-1 不得单独成边）、**按活动阶段对齐**、**ISO 兄弟条款消歧**。未做这些之前，准确率不会跨过 30% 线。
